
# Ingolstadt Hbf — Dispatching Analytics

AnyLogic выполняет дискретно-событийную симуляцию и выгружает результаты. Python читает и проверяет исходные CSV, рассчитывает показатели и парную статистику. Streamlit показывает интерактивные графики Plotly и таблицы по завершённым прогонам. Запуск и визуализация модели относятся к AnyLogic, где также запланирована отдельная трёхмерная визуализация.

## Установка и запуск

Выполните команды установки и запуска из корня репозитория.

```bash
python -m pip install -r analysis/requirements_dashboard.txt
python -m streamlit run analysis/station_dashboard.py
```

Откройте [локальный dashboard](http://localhost:8501), если браузер не открылся автоматически. Для запуска dashboard доступ к AnyLogic и интернету после установки зависимостей не требуется.

## Выбор данных и сценариев

- В **Results directory** укажите папку с файлами результатов и входными сценариями. По умолчанию используется `Ingo/results`. Относительный путь отсчитывается от корня репозитория.
- В **Aggregate scope** выберите серию, модель перехода и её параметры. При наличии соответствующей конфигурации по умолчанию выбирается MATRIX Monte Carlo с 4 минутами между островами и 1 минутой внутри острова. Выбор диспетчеров меняет отображение отдельных рядов. Парные показатели используют обе стратегии.
- В **Individual scenario** отдельно выберите конфигурацию, Scenario ID, Random seed и диспетчер. Этот выбор относится к диаграмме Ганта, очереди и таблице поездов. Состав серии Монте-Карло от него не зависит.
- В **CSV validation and exclusions** показаны статусы и причины исключения. Сводная строка показывает число обнаруженных экспериментов, полностью проверенных пар и допущенных к агрегированию пар.
- После записи новых файлов нажмите **Refresh CSVs**. Кэш учитывает каталог, имена, размер и время изменения файлов, в том числе входных сценариев.

## Форматы и проверка CSV

Пара определяется идентификатором сценария и числовым значением seed в имени файла. Для `P2_MATRIX_T4_S001` и seed `101` используются следующие имена файлов.

```text
train_results_FIXED_DB_P2_MATRIX_T4_S001_seed101.csv
train_results_GREEDY_P2_MATRIX_T4_S001_seed101.csv
delay_scenarios_P2_MATRIX_T4_S001_seed101.csv
```

Исторические выгрузки, например `S002` и `S101`, содержат расписание, входное опоздание, время готовности, назначенную платформу, её фактическую занятость, минимальную стоянку, ожидание и вторичную задержку. Старый формат UNIFORM добавляет поля `transfer_time_setting`, `assignment_time`, `passenger_transfer_min`, `passengers_ready_time` и `passenger_induced_delay_min`. Современный формат дополнительно содержит `transfer_mode` и `same_island_transfer_setting`. В UI отсутствующие пассажирские показатели помечаются как недоступные, а отсутствующие поля поездов скрываются.

Произвольные идентификаторы сценариев поддерживаются при соблюдении шаблонов имён файлов. Для новой серии Монте-Карло используйте общий префикс и суффикс вида `_S001`. Например, `WINTER_2040_T4_S001` и `WINTER_2040_T6_S001` войдут в серию `WINTER_2040`. Маркер `_T<число>` в имени помогает выделить серию. Настройки времени перехода берутся из CSV. Исторические, одиночные, базовые, повторные и тестовые сценарии доступны в индивидуальном анализе при прохождении проверки пары.

Проверяются уникальность Train ID и файлов, совпадение поездов, стратегии, идентификатора и seed, исходное расписание и входные задержки, число поездов, допустимость назначения платформ, отсутствие перекрывающихся интервалов занятости, числовые значения, расчёт ожидания и вторичной задержки. При наличии пассажирских полей проверяются время перехода, готовность пассажиров, фактическое отправление и прямая пассажирская задержка. Конфигурация пассажирской модели должна совпадать во всей паре. В сериях `P1_BATCH` и `P2_MATRIX` требуется 120 поездов на прогон. В новых сериях число поездов определяется по исходному сценарию.

- **Validated** означает, что проверены оба файла результатов и исходный сценарий.
- **Partial** означает, что оба результата согласуются, но исходный CSV отсутствует. Допустимость платформ по исходным данным подтвердить невозможно. Сценарий доступен для индивидуального анализа.
- **Incomplete** означает, что отсутствует один или оба файла результатов. **Invalid** означает ошибку файлов или данных.
- В агрегаты входят полностью проверенные пары из серий с одним наблюдением на seed внутри каждой конфигурации. Если seed повторяется в одной конфигурации, все её пары с этим seed исключаются.

## Загрузка платформ

Используется интервал от нуля до последнего фактического отправления среди всех допущенных прогонов выбранной серии. Для обеих стратегий и всех конфигураций одной серии знаменатель одинаков. Настройка остановки AnyLogic в 500 минут в расчёте не используется. Для полной серии MATRIX общий горизонт по исходным CSV составляет 132 минуты.

Загрузка равна `100 × занятые минуты / общий горизонт`. Занятость измеряется от фактического прибытия на платформу до фактического отправления. Диапазон загрузки равен разности максимума и минимума по четырём платформам в каждом прогоне. Стандартное отклонение рассчитывается по всем четырём платформам. Сводные показатели усредняются по прогонам, а средняя стоянка по платформе взвешивается по поездам. Диапазон и стандартное отклонение выражены в процентных пунктах. Более высокая загрузка может быть вызвана долгой стоянкой и прямой пассажирской задержкой.

В матрице назначений строки соответствуют плановым платформам, столбцы — фактическим. На диагонали показаны назначения без перестановки. Переключатель **Assignment counts** меняет среднее на сценарий на суммарное число поездов.

## Пассажирская модель

В модели Gleis 2–3 находятся на одном острове, Gleis 4–5 — на другом. Без переназначения время перехода равно нулю. UNIFORM использует одно время перехода при любом переназначении, MATRIX использует отдельное время для перехода в пределах острова и между островами.

Переход может совпадать по времени с обычной стоянкой. Прямая пассажирская задержка равна превышению времени готовности пассажиров над возможным временем отправления без перехода, с нижней границей в ноль. Возможное отправление без перехода — максимум планового отправления и суммы фактического прибытия с минимальной стоянкой. Единица показателя — минуты задержки поезда. Пассажиропотоки и человеко-минуты в этой модели не рассчитываются.

## Статистика

Парная экономия равна `вторичная задержка FIXED_DB − вторичная задержка GREEDY` для одного исходного сценария. Положительные значения соответствуют меньшей задержке у GREEDY, отрицательные — у FIXED_DB. Процент агрегированного снижения равен `100 × (Σ FIXED_DB − Σ GREEDY) / Σ FIXED_DB`. При нулевом знаменателе процент не определён.

Для среднего парного эффекта используется двусторонний 95%-й интервал Стьюдента по разностям отдельных сценариев. При единственном сценарии интервал и выборочное стандартное отклонение недоступны. Результаты разных конфигураций в один интервал не объединяются.

При анализе чувствительности сравниваются конфигурации внутри выбранной серии и между сериями UNIFORM и MATRIX из фаз 1 и 2. Для каждой пары конфигураций совпадение общих seed подтверждается по Train ID, расписанию, входным задержкам, готовности, группам маршрутов, спискам допустимых платформ и минимальной стоянке. Расхождения и отсутствующие seed отображаются отдельно. Значения рассчитываются только для реально испытанных настроек.

## CSV-экспорт

Кнопки **Download …** экспортируют таблицы с действующими фильтрами. Доступны сводки, данные по платформам, матрицы назначений, статистика, отчёт проверки, отфильтрованные поезда и сравнение выбранного поезда. Имена файлов содержат конфигурацию или идентификатор сценария и seed. Для импорта в электронную таблицу выберите UTF-8 и запятую как разделитель.

## Тестирование

```bash
python -m unittest discover -s tests -v
```

Набор включает искусственные CSV во временных папках, сверку с сохранёнными сводками в `analysis/output/` и навигацию по dashboard через Streamlit AppTest. В командах ниже замените `<temp-dir>` на путь к временному каталогу.

```bash
python analysis/analyze_results.py --scenario-glob "P2_MATRIX_T4_*" --expected-trains 120 --output <temp-dir>/matrix-t4
python analysis/analyze_platforms.py --output <temp-dir>/platforms
```

Для PNG-графиков командных скриптов нужен Matplotlib. Он не требуется для запуска dashboard.

## Устранение неполадок и ограничения

- Если сценариев нет, проверьте путь, окончания `_seed<number>.csv` и наличие обоих файлов результатов. После экспорта обновите список кнопкой **Refresh CSVs**.
- Если пара отсутствует в статистике, откройте **CSV validation and exclusions**. Например, сохранённый `P1_T5` содержит разные пассажирские настройки у двух стратегий.
- Если порт 8501 занят, укажите другой через `--server.port 8502`.
- Исторические файлы без пассажирских колонок пригодны для анализа движения и платформ. Для частично проверенных пар доступны индивидуальные графики и записи, но не статистические выводы.
- Результаты относятся к синтетическому расписанию, принятым правилам совместимости и предполагаемому времени перехода. Интеграция реального расписания и калибровка по измерениям относятся к следующим этапам.
